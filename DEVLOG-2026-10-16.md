# AnalogueWay Devlog — 16 October 2026

**Focus:** script cleanup and the power-up ("talisman") refactor
**Engine:** Unity 2021.3.8f1 · C# · 2D
**Result:** the game plays as before, the old card system is replaced, and power-ups were play-tested and work.

---

## Ground rules for the day

The game already worked, so the main rule was **behaviour must not change**, except where we chose to change it.

- Never edit `PlayerControls.cs`. Unity generates it from the input actions.
- Do all file renames, moves and deletes in the Unity Editor so each script's `.meta` GUID survives. Scenes and prefabs find scripts by GUID.
- Keep serialized field names, or add `[FormerlySerializedAs]`, so Inspector values survive.
- Make small changes and review each one before the next.

To check every change without leaving the terminal, I set up a compile check that runs **Unity's own compiler** (the Roslyn bundled with 2021.3.8f1) against the project's references and defines. Every edit below passed it before it reached the Editor.

## 1. Script audit

I reviewed all 43 scripts in `Assets/Scripts/` and checked each one against the scenes and prefabs to see which are actually attached. The findings fell into five groups:

1. **Dead code and unused fields:** empty `Start`/`Update` methods, about 20 unused fields, unused statics, commented-out code, and scripts that are empty or not attached to anything.
2. **Public static state used to talk between scripts:** `speedBoostPowerUp`, `chi`, `pLivesCount`, `coinCollected`, `lWorld` and others. Several of these carry over into the next scene without meaning to.
3. **Naming problems:** the class `CharecterBehaviour` sits in `CharacterBehaviour.cs`; `MainMenue` sits in `MenueController.cs`, so Unity can't load it; there are lowercase class names, and spellings like `lenght` in serialized fields.
4. **Duplicated logic:** mirrored ToriGate scripts, `MovingTiles` and `MoveJapanBoss`, the two jump boxes, the two branches of `changeWorld.Update`, and the AudioManager lookup copied into six scripts.
5. **Likely bugs:** 14 in total (listed under "Known bugs" below). None are fixed yet; each one changes behaviour and needs its own decision.

From this came a **9-step cleanup plan**, ordered from no risk to the most risk:

## 2. Step 0: the compile error that stopped everything

**Symptom:** the game wouldn't enter Play mode.

```
Assets/Scripts/PlayerController.cs(266,26): error CS0111: Type 'PlayerController'
already defines a member called 'CharJump' with the same parameter types
```

**Cause:** an untracked `Assets/claudeedits/` folder held second copies of `PlayerController`, `LevelManager`, `HurtPlayer`, `EnemyController`, `StompEnemy` and `NextLevel`. Unity compiles everything under `Assets/` into one assembly, so each class existed twice, and the compiler reported every member as a duplicate.

**Fix:** I moved the folder out of `Assets/` to the project root. Unity stopped compiling it and the errors went away.

## 4. The power-up refactor: cards → talismans

### Why

`ActiveCardManager` hard-wired three "cards" (keyboard Z/X/C plus three gamepad actions) and mixed input, cooldowns, sprites and effects together. The card UI was already gone, but about seven scripts still read its statics. That caused several problems:
- Adding a power-up meant editing about 7 places.
- Effects were re-applied every frame.
- The statics carried over into the next scene.
- There were latent bugs: the jump multiplier was applied to run speed, jump speed was reset to a hard-coded `5.0f`, and the blocked scenes were raw index numbers.

### The new design

- **`Talisman`** (ScriptableObject): holds the duration, cooldown, retrigger-while-held flag, traits, blocked scenes, an optional animator bool and a sound. It has the hooks `CanActivate`, `OnActivated` and `OnDeactivated`.
- **`SpeedBoostTalisman`:** the dash. It can only start while grounded.
- **`SuperJumpTalisman`:** multiplies the default jump speed.
- **`PowerUpManager`:** owns input, timers, activation, expiry and traits.

Other scripts now ask about **effects, not specific power-ups**:

```csharp
PowerUpManager.Has(TalismanTrait.EnemyImmunity)
PowerUpManager.Has(TalismanTrait.DefeatsEnemiesOnContact)
```

Adding a power-up now means creating an asset, or writing one small subclass. The manager never needs to change.

### What I checked before touching anything

| Finding | What it meant |
|---|---|
| The new scripts were in `claudeedits/`, outside the project | They had to be copied into `Assets/Scripts/` first |
| `ActiveCardManager` lives in one prefab used by all 20 level scenes | The slots only need setting once, on the prefab |
| `playerBodyDetectionArea` had a condition, not the early return the brief described | An early return would also have skipped checkpoints, chi stones and world switches during a dash, so only the condition changed |
| **Dash speed was different in different scenes** (16 to 21.6) because of per-scene overrides | We picked one value for every scene |
| `CardCoolDownTimer` sits under `DeckHolder`, which is inactive in every Z scene | It never ran in the final game, so it could be deleted |
| Only scenes starting with **Z** (including the village) are in the final game | Older scenes were ignored when making decisions |

### Decisions

- **Dash speed is the same everywhere.** It's based on Z3A2: 4 × 4 = **16**, which is a multiplier of **3.5556** on `speedDefault` 4.5.
- **Super jump stays the same:** 4.5 × 1.8 = **8.1**, which is a multiplier of **1.62** on the new `jSpeedDefault` of 5.
- **`CardCoolDownTimer` and `WalkOnAirCard` are deleted.** WalkOnAir is no longer a feature.

### The steps, ordered so the project compiled after every one

1. **Code:** `PlayerController` gained `jSpeedDefault = 5f`, `GetJSpeedDefault` and `PlayerAnimator`, and sets `speed` and `jSpeed` from their defaults in `Awake`.
2. **Editor:** copied `Talisman.cs`, `SpeedBoostTalisman.cs` and `SuperJumpTalisman.cs` into `Assets/Scripts/`.
3. **Editor:** renamed `ActiveCardManager.cs` to `PowerUpManager.cs`, which kept GUID `9c25537e…` so every scene kept its component. Then deleted `CardCoolDownTimer.cs` and `WalkOnAirCard.cs`.
4. **Code, one batch:**
   - put the `PowerUpManager` code into the renamed file
   - replaced every `ActiveCardManager.speedBoostPowerUp` check with a trait check, each marked `// POWERUP:`
   - removed the per-frame `SpeedBoost` animator code, since the talisman now sets it
   - made respawn call `PowerUpManager.Instance.ResetAll()`
   - removed the dead `wOnAirCardScriptRef` field
5. **Checked:** no references to the old statics remain, and it compiles cleanly.

| File | Change |
|---|---|
| `HurtPlayer` | `!PowerUpManager.Has(EnemyImmunity)` |
| `playerBodyDetectionArea` | `!PowerUpManager.Has(EnemyImmunity)` |
| `PlayerController` (knockback) | `!PowerUpManager.Has(EnemyImmunity)` |
| `EnemyController` | `PowerUpManager.Has(DefeatsEnemiesOnContact)` |
| `StompEnemy` | `!PowerUpManager.Has(DefeatsEnemiesOnContact)` |
| `LevelManager.RespawnCo` | `ResetAll()` on respawn |
| `NextLevel` | old reset removed |

### The "nothing happens" moment

In the first play-test the power-up keys did nothing. The code was fine. **No talisman assets had been created yet, and the manager's slots were empty**, so it skipped every key press. The old system had its numbers in code; the new one reads them from assets. After creating the three assets and assigning them on the prefab, everything worked.

| Slot | Key | Talisman | Settings |
|---|---|---|---|
| 1 | Z | Plain | 7 s, no traits |
| 2 | X | Speed Boost | 0.5 s, held, EnemyImmunity + DefeatsEnemiesOnContact, `SpeedBoost` anim, blocked in Z4A1–Z4A3, ×3.5556 |
| 3 | C | Super Jump | 1 s, held, ×1.62 |

### Intentional changes in behaviour

- The dash only starts on the ground and ends when its time runs out. It can no longer be stretched out in mid-air.
- A power-up that can't activate no longer uses up the cooldown or plays the sound.
- Gamepad presses during a cooldown are no longer remembered.
- Each talisman has its own cooldown; "one active at a time" is kept.
- Respawning clears active power-ups and cooldowns.
- The player walks at 4.5 from the start. Before, it was 4 until the first card was pressed.
- Dash speed is now the same, 16, in every scene.

**Play-test result:** ✅ everything works and feels smooth.
