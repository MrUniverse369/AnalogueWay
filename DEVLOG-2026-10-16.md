## Ground rules

The game already worked, so the main rule was **behaviour must not change** unless we chose to change it.

- Never edit `PlayerControls.cs`. Unity generates it from the input actions.
- Do all file renames, moves and deletes in the Unity Editor so `.meta` GUIDs survive. Scenes and prefabs find scripts by GUID.
- Keep serialized field names, or add `[FormerlySerializedAs]`.
- Leave scene, prefab and `.asset` edits to the Editor. Code changes come with a checklist of Editor steps.
- Make small changes and review each one. Changed lines are marked by feature: `// POWERUP:`, `// SAVE:`, `// SFX:`, `// MIX:`.

**How code was checked:** every change was compiled outside the Editor with **Unity's own compiler** (the Roslyn bundled with 2021.3.8f1) against the project's references and defines.

**How audio was checked:** every generated track and sound was checked for length, peak, clipping and loudness, and every loop for clicks at the loop point. None of it could be listened to during the session; the play-testing was done by ear in the Editor.

## 4. Power-up refactor: cards → talismans

**Before:** `ActiveCardManager` mixed input, cooldowns, sprites and effects together, and about 7 scripts read its statics.

**After:** a **talisman** system:
- `Talisman` (a ScriptableObject) holds the timing, traits and blocked scenes.
- `SpeedBoostTalisman` and `SuperJumpTalisman` add the effects.
- `PowerUpManager` handles input, timers and expiry.

Other scripts now ask about effects, not specific power-ups:

```csharp
PowerUpManager.Has(TalismanTrait.EnemyImmunity)
PowerUpManager.Has(TalismanTrait.DefeatsEnemiesOnContact)
```

**Key decisions:**
- **One dash speed for every scene**, based on Z3A2: 4 × 4 = **16**, a multiplier of **3.5556**. It used to vary from 16 to 21.6 between scenes.
- **Super jump stays the same:** 8.1, a multiplier of **1.62** on the new `jSpeedDefault` of 5.
- **Only Z scenes count** (including the village). Older scenes were ignored when making decisions.
- `CardCoolDownTimer` and `WalkOnAirCard` were deleted.
- `playerBodyDetectionArea` changed only its condition. An early return would also have skipped checkpoints and world switches during a dash.

**The rename:** `ActiveCardManager.cs` became `PowerUpManager.cs` in the Editor, keeping its GUID so all 20 scenes kept the component.

**The first test** did nothing at all, because no talisman assets existed yet. After the three assets were created and the slots filled on the prefab, everything worked.

| Slot | Key | Talisman | Settings |
|---|---|---|---|
| 1 | Z | Plain | 7 s, no traits |
| 2 | X | Speed Boost | 0.5 s, held, EnemyImmunity + DefeatsEnemiesOnContact, `SpeedBoost` animation, ×3.5556, activation sound `Dash.wav` |
| 3 | C | Super Jump | 1 s, held, ×1.62 |

**Intentional behaviour changes:**
- The dash only starts on the ground, and ends when its time runs out.
- A power-up that can't activate no longer uses up the cooldown or plays the sound.
- Each talisman has its own cooldown; "one active at a time" is kept.
- Respawning clears active power-ups.
- The player walks at 4.5 from the start (before, it was 4 until the first card was pressed).

## 5. Save system

**Goal:** remember progress (coins, lives and so on) between sessions, in a system that's easy to change later.

**Design: four small pieces, each replaceable on its own.**

| Piece | Job |
|---|---|
| `SaveData` | The saved data only: scene name, coins, lives, chi, deaths, current world, version, timestamp |
| `SaveStorage` (`ISaveStorage`) | Where the save lives: `FileStorage` (readable JSON) in the Editor and desktop builds, `PlayerPrefsStorage` in WebGL and mobile |
| `SaveSystem` | The only code that knows the format: JSON, versions and upgrading old saves through `Migrate()`. It never crashes; a corrupt save counts as "no save" |
| `GameSession` | The only code that knows where game state lives: `NewGame`, `Capture`, `Apply`, `TryContinue`. When the statics are replaced, only this file changes |

**When it saves and loads:**
- **Autosave:** at checkpoints, and when leaving a level (`NextLevel`, `TownExit`).
- **Continue:** reopens the saved level from its start.
- **Play:** starts fresh (0 coins, 3 lives) and replaces the save.
- **Coins:** stay collectable again when a level is replayed.

**Gameplay change:** `HurtPlayer.Start` used to reset lives to 3 in every level, which was bug B4. Lives now carry over between levels and refill only on game over or New Game.

**Save location in the Editor:** `~/Library/Application Support/DefaultCompany/QPlatformer_One/slot0.json`. You can open and edit it by hand.

**Play-test:** ✅ works.

## 6. Two bugs found in play-testing

**The speed boost was blocked in the wrong levels.** The talisman blocked build indices 1–3. When Z4A1–Z4A4 were switched off in Build Settings, every index shifted, and the block landed on Z4A6, Z4A7 and an old scene. **Fix:** talismans now block by **scene name** (`blockedScenes`), so reordering or switching scenes off can't move the block. This also fixes bug B8.

**The pause menu wouldn't open** in Z4A1–Z4A4, Z4A6 and Z1A3. Those scenes never had `Pause.prefab`, which holds the `MenueControl` component, and several have no EventSystem. This is an Editor fix (add the prefab and an EventSystem); see Still open.

## 7. Music

Every track is generated by a stdlib-only Python synth in `Tools/Music/`, loops seamlessly, is 44.1 kHz 16-bit stereo, and is mastered to the same loudness as the others.

| Track | Levels | Style |
|---|---|---|
| **SnowTemple_Modern** ✅ approved | Japan (Z3) | 125 BPM. D Phrygian with the *miyako-bushi* scale. FM electric piano, slap bass and brass, a shakuhachi verse, koto, taiko and hyoshigi; the chorus uses the "royal road" progression (B♭maj7 → C7 → Am7 → Dm7). 48 bars, 92 s |
| **SandyDunes** | Sandy (Z2) | 118 BPM. E *Hijaz*. Ney flute and oud verses, a brass chorus ending on an Arabian run, darbuka (*maqsum* rhythm), tambourine and finger cymbals. 81 s |
| **GrassyMeadow** | Grassy (Z4) | 126 BPM. G major with a swing. Whistle lead, brass chorus, glockenspiel, and a bridge that lifts to E♭ and F. 76 s |

**How the Japan theme got there:**
1. **First version** (`SnowTemple_Loop`): chiptune at 150 BPM. Feedback: too fast, and should be more modern (Sonic Mania, Super Mario 3D World).
2. **Pace from a reference track:** `POL-treasure-match-short.wav` measured **125 BPM**, exactly 8 bars. A first tempo reading of 166.7 BPM turned out to be its **3-3-2 (tresillo) kick pattern**, 0.36 s between hits.
3. **Second version** (`SnowTemple_Modern`): 125 BPM with that kick pattern in the chorus. Approved, and left unchanged since.
4. **"Still playing the old music":** the new file had never been assigned. Every Japan scene overrides the AudioManager's music, so it has to be set per scene.

## 9. The mix pass

**The problem:** the music played at about **−30 dB** (its AudioSource was at 0.2), while effects ranged from **−29 dB to −10 dB**. Coins were about three times as loud as the music to the ear, and jumps barely rose above it.

**The method:** I measured every clip the same way (the loudest 400 ms after a 100 Hz high-pass) and set each sound to a level relative to the music:

| Level vs music | Sounds |
|---|---|
| Just under (−3 dB) | Footsteps |
| Slightly under (−2 to −4 dB) | Jump, coin, dash, living-world gate |
| Level (±1 dB) | Enemy defeats, chest, checkpoint, power-up, bounce, hurt |
| Just above (+1 to +2 dB) | Dragon summon, KO, win, spirit-world gate |

**What changed:**
- **The music** now plays at **0.35** (`musicVolume`).
- **Generated sounds** are rendered at their target level (`loud_db` in the tools).
- **Third-party sounds** get volumes in **AudioManager → Mix**, from the measurements: coin 0.18, bounce 0.30, win 0.54, power-up 0.79, jump 0.82.
- **Overlapping one-shots** play on their own AudioSource, so their volumes can't interfere with `PlaySfx`, which still cuts off and restarts as before.
- **Footsteps** later got about 5.5 dB louder (`Footstep Volume` stays at 0.6), and **the spirit-world gate** about 3 dB louder.

This is one game-wide mix. The older stock music (`BGM_02`, `ArcadeGameBGM#3_Loop`) hasn't been measured yet.

## 10. Tools added

Everything lives outside `Assets/`, uses only the Python standard library, and re-renders in seconds.

| Script | Renders |
|---|---|
| `Tools/Music/snow_temple_modern.py` | `Assets/Music/SnowTemple_Modern.wav` (kept as-is: approved) |
| `Tools/Music/arcade_synth.py` | Shared engine: FM electric piano, bass, brass, bells, plucked strings, flute, strings, full drum kit with taiko and darbuka, reverb, mastering |
| `Tools/Music/sandy_dunes.py` | `Assets/Music/SandyDunes.wav` |
| `Tools/Music/grassy_meadow.py` | `Assets/Music/GrassyMeadow.wav` |
