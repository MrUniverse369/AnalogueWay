## Request 2: replace every sound effect with ElevenLabs sounds (not the music)

### What was asked
Generate new sounds with ElevenLabs and swap them in for every sound in the game except the background music. Each sound should really fit its object or action.

### What was done

**Finding the sounds**
- Every audio clip was traced to where it's used: the `AudioManager` prefab, the menu catalog (`HNLCatalog.asset`), the zone map scene and the talisman assets.
- Some clips were doing several unrelated jobs:
  - the jump-pad "boing" was also the Yokai boss's ground slam
  - the talisman sound was also the boss defeat sound
  - the coin sound was also the shop purchase sound
  - the chest sound was also the item pickup sound
  - only Spirit Dash had its own talisman sound
- The sprites were checked so the prompts matched the objects. For example, the checkpoint is a golden lantern post that lights with a green flame.

**Generating**
- 33 prompts were run on one ElevenLabs flow (`mVAqVfpJqNay2ZRo8tyl`), 4 variations each, for about 2,200 credits in total.
- All variations are kept on the flow, so you can swap any sound later.
- Footsteps and the menu tick were made by cutting single hits out of longer clips, because single-hit prompts came back nearly silent or full of several clicks.

**Choosing**
- The sounds were not listened to. Each variation was scored on measured traits: length, number of separate hits, attack speed, brightness and background noise.

**Fitting into the mix**
- Each new clip was trimmed, faded, and set to the same loudness as the clip it replaced *as heard in game* (its raw level × its `AudioManager` volume slot), so your mix is kept.
- Exceptions:
  - Game over is a little louder; the old clip was too quiet.
  - Menu "back" is quieter; the old one was about 4× louder than the other menu sounds.
  - The spring pad and equip sounds hit the limit for distortion, so `bounceVolume` went from 0.30 to 0.43 to compensate.
- The files are in `Assets/Sound/ElevenLabs/{Player, World, Enemy, UI, Talismans}/HNL_*.wav`. The old clips are still in the project, just unused.

**Code**
- `AudioManager.cs` has new `bossSlamSound` and `bossDefeatSound` slots, which fall back to the old sounds if left empty.
- `YokaiBoss.cs` uses the new slots.
- Every talisman now has its own activation sound.

| Where | New sound |
|---|---|
| Harvey | jump whoosh, 4 paw steps on stone, cat yelp (hurt), sad woodwind (game over), marimba-and-bells (level complete) |
| World | coin ting, spring boing, lantern lighting with a chime (checkpoint), chest creak and sparkle, dragon gust and roar |
| Torii gates | temple bell (into the living world), ghostly swell (into the spirit world), breeze and wind chimes (zone map) |
| Enemies and boss | squish (stomp), whoosh-thwack (dash), stone landing thud (boss slam), spirit dissolving (boss defeat) |
| Menus | wood tick (cursor), tap and bell (confirm), low tock (back), dull thunk (blocked), clasp and shimmer (equip), coins into a pouch (buy), rising sparkle (pickup) |
| Talismans | Spirit Dash gust, Coin Magnet hum and jingle, Stone Skin grinding rock, Water Breathing bubbles, Feather Fall airy chimes, Super Jump spring launch |

### Tested
- On disk, every new clip is referenced and no old sound effect is used anywhere.
- The music references were unchanged, and the console had no errors.

## Request 4: five save files, Play / Continue, and Arcade mode

### What was asked
- Up to 5 save files.
- **Continue** lists them to pick from.
- **Play** picks an existing file or starts a new one, and asks to overwrite when all 5 are full.
- **Arcade:** an unsaved mode where Harvey respawns where he died.
- Picking, loading, creating and overwriting files must never affect other files.

### What was done

**Saving** (`SaveSystem.cs`, `GameSession.cs`)
- There are 5 files, `slot1`–`slot5`.
- Every save and load uses the **active file**, the one being played, which is remembered between runs.
- Your existing save (`slot0`) moved into File 1 automatically, and the old key was removed after the copy was checked.
- Starting a new game in a file clears that file only, including its zone-map unlocks.

**Save-file screen** (new `SaveSlotMenu.cs`)
- It's built in code in the pause menu's style: frame, plaque, cards, paw pointer and menu sounds.
- Each file shows its location (using the zone map's level names), coins, the date saved, and LAST PLAYED.
- **Continue:** picks a used file. Empty files are greyed out and can't be picked.
- **Play:**
  - An empty file starts a new game.
  - A used file asks CONTINUE / NEW GAME / CANCEL.
  - NEW GAME asks "Start over in File N? Its saved progress will be lost." with **CANCEL selected by default**.
  - When all 5 files are full, the hint turns orange: "ALL FILES IN USE: PICK ONE TO CONTINUE OR REPLACE".
- Circle/Esc backs out one step at a time.

**Main menu**
- `MenueControl.LoadFirstLevel` and `ContinueGame` open the screen, so the existing button bindings didn't change.
- A new **ARCADE** button was added. It's a copy of Zone Select with a joystick icon from `Tools/Art/main_menu.py` (`Icon_Arcade.png`), wired to `MenueControl.StartArcade`.
- The four buttons now sit at y −1, −23, −45 and −67, so ARCADE clears the "A Set 8 Jams Game" credit. Navigation wraps from PLAY to ARCADE.

**Arcade** (`GameSession.IsArcade`, `LevelManager.cs`)
- A fresh run from level 1 that never saves; checkpoints, the shop and level exits write nothing.
- The pause menu shows "ARCADE: PROGRESS IS NOT SAVED". Going back to the main menu, or picking Zone Select, ends the run.
- On game over Harvey respawns on the last **solid, non-moving ground he stood on**. That means:
  - not the exact death spot, which might be a pit or spikes
  - not a moving or falling tile, an enemy or a hazard
- If he hasn't stood anywhere safe yet, he falls back to the checkpoint.

**Other**
- The zone map's coin label now shows "FILE n".
- `LevelManager.Start` keeps the player reference from the scene instead of re-searching for it. The search could miss a player hidden by a game over and leave the reference empty; the test found this.

### Tested in Play mode
- The old save showed as File 1. After testing, its content was byte-for-byte identical to the original.
- **New game in empty File 2:** File 2 was created fresh (Old Tomb Act 1, 0 coins, only Act 1 unlocked), and File 1 was unchanged.
- **Overwrite:** NEW GAME → confirm (CANCEL default) → CANCEL left File 1 untouched. OVERWRITE on File 5 changed only File 5; Files 1–4 were byte-identical before and after.
- **All five files in use:** the orange hint appeared.
- **Arcade:**
  - triggering a checkpoint save wrote nothing
  - game over in mid-air respawned Harvey at the last safe ground he stood on, (11.75, −3.47), not the checkpoint at (3.75, −1.90)
  - lives reset to 3
- Bugs found and fixed during testing:
  - the paw overlapped the buttons in the question box, so the gap between buttons was widened
  - focus didn't always return to the chosen file after Cancel
  - the ARCADE button overlapped the credit
- The test files were deleted afterwards, and File 1 is set as last played.

### Not done
There's no way to delete a file except overwriting it. It can be added if wanted.

## Request 5: performance sweep

### Measured (Play mode, six of the busiest levels)

| | Result |
|---|---|
| Frame time | 2–3 ms in the editor; 60 fps allows 16.7 ms |
| Game scripts | 0.03–0.11 ms per frame |
| Physics | ~0.01 ms per frame |
| Draw calls | 10–47 batches |
| Garbage from game code | after the fixes, 112 bytes over 238 frames (the timer label once a second, plus one-off compilation) |

The ~10 KB per frame of garbage reported overall comes from the Unity editor's own windows, not the game.

### What was fixed
- **`FadeIn.cs`:** it restarted `CrossFadeAlpha` every frame, which created a new fade each time. It now sets the alpha directly. The fade curve was measured and is the same e^(−t/2) ease-out.
- **Music streaming:** the 4 new zone tracks, `ArcadeGameBGM#3_Loop` (zone map) and `Temple` were set to *Decompress On Load*, about 11 MB of raw audio each, decoded when a level loads. All six now stream like the other tracks.
- **Sound-effect preload:** the 34 ElevenLabs clips had preload off, so each one loaded from disk the first time it played. They now load with the level.
- **HDR off** in `Assets/URP/URP.asset`: no scene uses post-processing or volumes, so it looks identical and saves graphics memory every frame.
- **Small per-frame tidy-ups:**
  - the main menu paw and the save-file screen reuse one array instead of making a new one every frame
  - the Arcade ground check remembers the ground it last inspected

### Checked and left alone
- **Textures:** the pixel art is uncompressed, which is correct, and none have mipmaps or Read/Write on. The three 2048 px tutorial images are only used in the disabled Z4A1/Z4A4 levels.
- **V-Sync** is on.
- **Physics settings** are fine, and no scripts use collision callbacks.
- **HUD scripts** only update text when the value changes.

### Suggestion
The build target is now macOS, not WebGL. For release, building with **IL2CPP** instead of Mono (Player Settings) would run the game's code faster. It needs the IL2CPP module in Unity Hub, so it wasn't changed.
